EventTracer 架构

把「这里没声音」拆成七种可区分的失败模式，并为每一次事件调用留下足以复现的现场记录。 本文是 Phase 0–2 交付内容的架构总结。

起点

问题

PlayOneShot 什么都不返回。一个因超出 max instance 被拒的实例、一个跑出衰减范围被虚拟化的实例、 一个被后来者抢走发声位的实例，和一个播得好好的实例，从调用点看完全一样：没有异常，没有日志，只有沉默。

EventTracer 的做法是让调用走统一门面，由门面持有实例的整个生命周期，从而把这四种（以及另外三种）情况区分开。 代价是要改调用点；收益是「没声音」从一个症状变成七个可验证的判断。

PHASE 0 门面与记录模型 统一入口、后端接口、AudioTraceRecord、Native 兜底后端。
PHASE 1 环形缓冲与落盘 定容缓冲、字符串驻留表、后台写盘线程、.adtrace 格式。
PHASE 2 FMOD 结果归一化 回调订阅、信号翻译、七种 Outcome 的判定与实测验证。
核心

信号路径

整个模块的架构决定只有一条：判定谁来做。后端只把中间件的回调翻译成一组与中间件无关的信号， 判定「这串信号意味着被抢占还是被主动停掉」发生在 Core 的纯函数状态机里。 这样最容易出错的那部分代码，可以在一台没装任何中间件的机器上用表驱动测试跑完。

词汇

七种 Outcome

结果 含义 FMOD 侧判定
HandleInvalid 拿不到句柄：bank 未加载，或事件名拼错 RESULT != OK
Rejected 实例建出来了，但没拿到发声位 CREATED 后未见 STARTED 即 DESTROYED
Started 正常起播，或已播完 STARTED
Virtualized 在播，但不出声：出了衰减范围、太安静、超发声数 REAL_TO_VIRTUAL
Stolen 被引擎抢走发声位 早于事件时长停止，且无人请求
StoppedEarly 被游戏逻辑提前停掉 早于事件时长停止，且有人请求
NotCalled 代码根本没跑到 本模块不产生 —— 见下方边界

Virtualized 是黏性的：一个声音中途虚拟化过又恢复，记录仍保留这个结论， 因为「中间断了一下」正是有人在反馈的现象，改回 Started 会抹掉唯一的证据。 但若它随后被切断，切断的原因胜出——那才是最终沉默的解释。

距离在无位置可测时记 -1 而不是 0。零会被读成「就在听者头上」，是个看起来合理的错误答案。

边界

程序集与编译开关

采集层随包进玩家端，所以它必须能被整体编译掉。 关掉 AUDIOTOOLBOX_TRACE 后，反射确认下列类型在程序集中完全不存在； 留下的是播放基础设施与纯数据类型。

常驻

门面与播放所需。声音结束时发声位要回收、句柄要保持可安全持有，这些与是否记录无关。

  • AudioTrace 门面
  • IAudioRuntimeProbe 后端接口
  • VoiceRegistry 发声位与代次
  • ProbeSignalQueue 跨线程队列
  • AudioTraceRecord · TraceFormat 纯数据

宏内 · 关闭即消失

Runtime/Recording/ 整个目录。日志读取器住在 Editor 程序集且不受此宏约束——要看的日志来自别人的构建。

  • OutcomeStateMachine
  • TraceRingBuffer
  • StringInternTable
  • TraceRecorder
  • TraceSessionWriter

后端通过 [RuntimeInitializeOnLoadMethod] 自注册，Core 从不点名任何一个后端。 与模块 C 用 TypeCache 反射发现不同——那是编辑器侧，反射不要钱； 这里是运行时路径，启动时扫全部程序集在主机平台上是实打实的开销，且 IL2CPP 下还得手工保活。

取舍

三个关键决定

测试性

判定不在后端里

回调时序是中间件文档与实际行为最容易分家的地方，也是本模块最可能写错的部分。 把它放进不依赖 Unity、不依赖中间件的纯函数里，EditMode 表驱动测试就能覆盖全部七种； PlayMode 用真 FMOD 回答另一个问题：引擎是否真的发出那串信号。两个问题分开，红灯才有具体含义。

零 GC 的前提

一切字符串都是 int

记录是 struct，存在一个定容数组里，事件名、调用点全部走驻留表存索引。 否则几万条记录会把托管堆拖成 GC 的遍历对象，日志体积也会失控。 调用点由 [CallerFilePath] 提供，是编译期常量；「文件:行号」按调用点缓存，每个调用点只拼一次字符串。

诚实

丢了就说丢了

缓冲溢出、队列溢出、驻留表满、写盘失败，全部计数并写进会话头。 一个被截断却自称完整的会话，会让人得出「这个声音从没被调用过」的结论——那正是本模块要避免制造的错误。
